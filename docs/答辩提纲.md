# 答辩与演示提纲

## 三分钟流程

1. 说明英文短信辅助分流的范围；LLM负责选工具与解释，课程LR负责分类证据。
2. 打开网页，展示三模式。交付Key为空；真实模式会提示配置缺失，不能声称已经联网。
3. 选择“离线协议演示”，运行短链接样例。明确模型响应来自脚本，工具结果真实。说明真实模式用相同执行器接收API返回的工具调用。
4. 查看分类、规则检索、链接检查、证据提交的轨迹。指出多轮消息如何回传tool_call_id。
5. 人工保持复核或修正决定，完成任务并导出JSON。此处只更新任务状态，不删除短信，不重训。
6. 展示原公开分类结果F1=0.9333和45项软件测试；不把这两个数说成LLM任务成功率。

## 应能回答

- Agent在哪里：LLMAgent.run逐轮请求模型，校验并执行工具，再回传观察，直到有依据的提交或到达预算。不是只给分类结果润色。
- 为什么还有固定规则：LLM选择合法工具，程序控制权限、输入绑定、证据要求和停止条件。可规划不代表可以绕过约束。
- 是否真的调用过LLM：本次没有真实密钥，所以没有。已实现API请求和执行循环，测试以替代响应验证协议，界面演示明确是模拟。
- 如何真实验证：填写.env，选择支持工具调用的模型，运行evaluate_llm_live.py，再做代表性任务评估。三例接口验收不算全面评测。
- 传统ML有什么用：classify_sms返回实际训练模型的分数和特征。LLM必须引用它；不得直接用语言判断替代课程模型。
- Skill是否运行：docs/SKILL.md每次读取后加入系统消息；工具规则另从JSON读取。该技能本项目自编，sklearn是外部复用。
- 人工确认有什么用：使建议进入可审阅的任务闭环。完成不代表预测必然正确，人工最终决定单独记录。
- TF-IDF：对数词频乘训练IDF并归一化，测试不能参与词表和IDF拟合。
- 为什么字符LR：验证和测试F1均优于词LR；字符解释可读性弱，需如实说明。
- 原拒判消融：0.49/0.50很窄，没减少测试错误；这是离线基线，不是新增LLM的实验。
- 主要局限：历史英文语料、非权威规则、未校准分数、LLM摘要可能出错、未联网实测、没有真人用户任务研究。

提交前阅读llm_agent.py、core.py、experiment.py和LLM_AGENT.md；亲自运行模拟演示。若准备现场联网演示，应提前验证自己的配置，不在公开屏幕或仓库展示密钥。
